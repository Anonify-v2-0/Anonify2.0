# Anonify Helm chart

**Anonify on Kubernetes with one `helm install`.** Anonify is self-hosted,
AI-assisted document redaction: upload a PDF, Word document, spreadsheet,
deck, email, mailbox, CSV, text file or image; Anonify proposes what looks
like personal data; a person decides; the export removes it.

This repository holds the **Helm chart**, as an OCI artifact. The application
image it runs is
[`nabeelwasif/anonify2.0`](https://hub.docker.com/r/nabeelwasif/anonify2.0).

Source, documentation and issues:
[github.com/Anonify-v2-0/Anonify2.0](https://github.com/Anonify-v2-0/Anonify2.0)

## Install

```sh
helm install anonify oci://registry-1.docker.io/nabeelwasif/anonify \
  --namespace anonify --create-namespace \
  --set database.url='postgresql://anonify:…@db.internal:5432/anonify' \
  --set storage.s3.bucket=my-anonify --set storage.s3.region=eu-west-1 \
  --set secrets.extra.S3_ACCESS_KEY_ID=… --set secrets.extra.S3_SECRET_ACCESS_KEY=… \
  --set publicUrl=https://anonify.example.com
```

That installs the newest release. Add `--version X.Y.Z` to pin one, which you
should for anything you keep. Then:

```sh
helm test anonify -n anonify                    # /api/ready through the Service
kubectl -n anonify port-forward svc/anonify-web 3000:80
```

and open <http://localhost:3000>.

## What you need first

- **PostgreSQL 15+**, reachable from the cluster: managed (RDS, Cloud SQL,
  Azure Flexible Server, Neon) or an operator (CloudNativePG).
- **Object storage**: S3 or anything S3-compatible (RustFS, MinIO, R2, GCS
  interop), or Azure Blob. Web and worker pods are separate, so local disk is
  refused.
- Optionally **[KEDA](https://keda.sh) 2.12+**, to scale workers on the
  queue and down to zero.

## What it installs

| Resource | What it does |
| --- | --- |
| `Deployment/web` | Pages, the API and progress streams, behind a `Service` and an optional `Ingress`. An HPA on CPU, 2 to 10 pods. |
| `Deployment/worker` | The job queue. Scaled by KEDA on queue depth (to zero if you like), or by an HPA on CPU with at least one worker. |
| `Job/migrate` | Database migrations before every install and upgrade. If it fails, the upgrade stops and the old pods keep serving. |
| `CronJob/cleanup` | Only when the workers' built-in expiry sweep is turned off. |

Plus liveness, readiness and startup probes, a graceful drain on every
rollout and scale-in, and `PodDisruptionBudget`s, so no document is lost to
a rollout.

## Secrets

`ENCRYPTION_KEY` seals every stored document. **Lose it and every document is
unreadable.**

- **Your own Secret (recommended)**, from External Secrets, Sealed Secrets or
  SOPS: `--set secrets.existingSecret=anonify`.

  ```sh
  docker run --rm nabeelwasif/anonify2.0 keys > anonify.env   # the three keys
  # add DATABASE_URL=… and your storage and AI keys, then:
  kubectl -n anonify create secret generic anonify --from-env-file=anonify.env
  ```

- **Generated by the chart** (the default): made on install, **read back on
  every upgrade, never regenerated**, and kept on `helm uninstall`. Back the
  key up anyway.

No static storage keys needed with IRSA, EKS Pod Identity, GKE workload
identity or Azure workload identity: annotate the service account instead.

## Values most installs set

| Value | Default | |
| --- | --- | --- |
| `database.url` | | `DATABASE_URL`; a pooler is fine |
| `database.workflowUrl` | | A direct connection, when `url` is a transaction-mode pooler |
| `secrets.existingSecret` | | Your Secret; see above |
| `storage.driver` | `s3` | `s3` or `azure-blob` |
| `storage.s3.*` | | `bucket`, `region`, `endpoint`, `forcePathStyle`, `presignedUploads` |
| `publicUrl` | | The URL people reach Anonify at |
| `env` | `{}` | Any other setting from `.env.example`, for every pod |
| `worker.autoscaling.mode` | `auto` | `keda` if KEDA is installed, else `hpa`; or `none` |
| `metrics.enabled` | `false` | `/api/metrics`, with an optional `ServiceMonitor` and Grafana dashboard |
| `image.digest` | | Deploy by digest; each release's notes give it |

Every value, with comments:
[values.yaml](https://github.com/Anonify-v2-0/Anonify2.0/blob/main/deploy/helm/anonify/values.yaml).
The full guide, including autoscaling, ingress annotations for progress
streams, and upgrades:
[chart README](https://github.com/Anonify-v2-0/Anonify2.0/blob/main/deploy/helm/anonify/README.md).

## Security

Pods run as UID 1001 with no capabilities, no privilege escalation, the
`RuntimeDefault` seccomp profile and a read-only root filesystem: they pass
the `restricted` Pod Security Standard. The service account token is not
mounted.

## Versions

The chart is versioned with Anonify, in lockstep: chart `X.Y.Z` installs
Anonify `X.Y.Z`. A published chart version never moves. Each
[GitHub release](https://github.com/Anonify-v2-0/Anonify2.0/releases) also
attaches it as `anonify-<version>.tgz`.

Requires Kubernetes 1.25+.

Search, RegEx rules, global rules and Hush, a review assistant, in the review
screen. `Ctrl/⌘+F` or `/` searches the whole document on the server, not just
the pages that are loaded. It works in every format with a review view, with
match case, whole word and RegEx options, an "N of M" counter announced to
screen readers, and amber highlights that move page by page. From a hit, you
can redact that match or open a rule for all of them, and optionally see
counts across the batch. Rules can now be RegEx as well as text. RegEx rules
run on a linear-time engine (RE2), so a pattern cannot hang the server;
backreferences and lookaround are refused, and a rule that matches too much
applies nowhere rather than partway. Every rule is previewed, with its count
and matches in context, before anything is written. Rules can also be global:
applied to every document you upload from now on, with the pattern encrypted
at rest and deleted after 30 days unused. Global rules can be exported and
imported as JSON. The inspector has a Rules tab listing every rule that
reaches the document, where each can be switched off, edited with a fresh
preview, or removed with everything it redacted. `Ctrl/⌘+K` opens Hush. It
offers a rule once you have redacted the same shape of value by hand a few
times (locally, with no AI provider needed), answers plain-language requests
with previewed rule proposals, and tightens a RegEx rule, showing which
matches it gains and loses. Hush only ever proposes. It says exactly what it
will send before sending, never sends the document, and uses the configured
provider within the same spend cap and `AiUsage` accounting as analysis. `?`
lists every keyboard shortcut. This release adds tables and columns, so run
`pnpm db:migrate:deploy` before starting it. A batch or global rule that
matches too much of a newly processed document now fails that document with
`rule-too-broad`. The document can still be reviewed, and retries once the
rule is narrowed
